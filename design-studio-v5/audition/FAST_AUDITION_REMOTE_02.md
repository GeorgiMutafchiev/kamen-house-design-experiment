# V5 fast audition addendum — two home-only captures

GitHub-hosted [run 37227072156](https://github.com/GeorgiMutafchiev/kamen-house-design-experiment/actions/runs/37227072156) captured `MOROSETA` and `SOMBRE` at both standard viewports. The source URLs are first-party and returned HTTP 200. The worker retained the natural opening state, logged a real click on each site's overlay control, waited for that control to disappear, traversed the page and stored full-page screenshots. Separate visual review found the final frames populated and free of the obstructing panels. Both sources are **home-only**; no rooms detail, booking flow, mobile menu interaction or business outcome was inspected.

`MOROSETA`: the first-party homepage uses an architectural doorway image, a compact wordmark and a consistent two-column sequence for property, rooms, kitchen, garden, boat and shop. The mobile layout converts this to a legible vertical sequence. The rooms image and “Stanze” label are visible; the page has a “Booking” nav item, but neither destination nor room decision support was captured. Small body text and low-contrast navigation limit the score. `SOMBRE`: desktop imagery, shadows and generous white space convey a coherent courtyard property. The mobile viewport, however, splits the wordmark into three awkward lines and the full-page screenshot exposes 768px document width in a 390px viewport. This is observed source behavior, so the capture is faithful, but it vetoes a broad mobile-quality role. A “BOOK YOUR STAY” desktop control and a rooms module appear; their destinations and the mobile path are untested.
